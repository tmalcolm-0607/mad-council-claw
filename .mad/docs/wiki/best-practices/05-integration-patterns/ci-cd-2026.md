# CI/CD (2026)

## Overview

Continuous integration and deployment patterns for AI-assisted development including GitHub Actions, GitLab CI, quality gate automation, hooks system (Q1 2026), and headless mode.

## Core Principles

| Principle | Description |
|-----------|-------------|
| **Quality Gates in CI** | Run full test suite + linting in CI |
| **Fail Fast** | Block merges on test/lint failures |
| **PR Checks** | All gates must pass before merge |
| **Hooks-Based Enforcement** | Transform guidelines into enforced rules |
| **Headless Automation** | Use CLI for scripting and pipelines |

## Patterns (Current)

### Hooks for CI/CD (Q1 2026)

**Released Q1 2026**: Production-ready hooks system.

**Transform guidelines into enforced rules**:
- Run quality gates (linting, type checking, security scanning)
- Execute automatically on PR/MR events
- Post results as comments on PR/MR
- Block merges until gates pass

**Example hook configuration** (`.claude/hooks/pre-commit.js`):
```javascript
export default async function(context) {
  const { changedFiles } = context;

  // Run linting
  const lintResult = await runLint(changedFiles);
  if (lintResult.failed) {
    return {
      allowed: false,
      message: "Linting failed. Fix errors before committing."
    };
  }

  // Run tests
  const testResult = await runTests(changedFiles);
  if (testResult.failed) {
    return {
      allowed: false,
      message: "Tests failed. Fix failures before committing."
    };
  }

  return { allowed: true };
}
```

### GitHub Actions Integration

**Quality gate workflow**:
```yaml
name: Quality Gates
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  gates:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'

      - name: Install dependencies
        run: npm ci

      - name: Run quality gates
        run: |
          npm run lint
          npm run type-check
          npm test
          npm run test:e2e -- --grep @p0

      - name: Comment on PR
        if: failure()
        uses: actions/github-script@v7
        with:
          script: |
            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body: 'Quality gates failed. Review the logs and fix issues.'
            })
```

### GitLab CI Integration

**Patterns** (from official docs):
- Configure hooks in GitLab CI pipeline
- Automatic execution on merge request events
- Status checks required for merge

**Example `.gitlab-ci.yml`**:
```yaml
stages:
  - test
  - quality

quality-gates:
  stage: quality
  script:
    - npm ci
    - npm run lint
    - npm run type-check
    - npm test
  rules:
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
  allow_failure: false
```

### Headless Mode

**CLI usage**: `claude -p "your prompt"`

**Output formats**:
- Plain text (default)
- JSON (`--output-format json`)
- Streaming JSON (`--output-format stream-json`)

**Use cases**:
- CI pipelines
- Pre-commit hooks
- Automated workflows
- Scripts

**Examples**:
```bash
# One-off queries
claude -p "Explain what this project does"

# Structured output for scripts
claude -p "List all API endpoints" --output-format json

# Streaming for real-time processing
claude -p "Analyze this log file" --output-format stream-json

# In CI pipeline
claude -p "Review changes in git diff" --output-format json > review.json
```

### Autonomous Mode (Use with Caution)

**Flag**: `--dangerously-skip-permissions`

**Use cases**:
- Fixing lint errors
- Generating boilerplate
- Contained workflows

**Security warning**: "Letting Claude run arbitrary commands can result in data loss, system corruption, or data exfiltration via prompt injection. Only use in container without internet access."

**Safer alternative**: Use `/sandbox` for OS-level isolation with defined boundaries.

**Example (containerized only)**:
```bash
# In isolated container
claude -p "Fix all lint errors" --dangerously-skip-permissions
```

### MCP Server Integration

**Command**: `claude mcp add`

**Connect external tools**:
- Notion (issue trackers)
- Figma (designs)
- Databases (query/analyze)
- Monitoring systems (analyze data)

**Automation workflows**:
- Implement features from issue trackers
- Query databases for CI checks
- Integrate designs from Figma
- Analyze monitoring data in pipelines

**Tool reference format**: Always use fully qualified names: `ServerName:tool_name`

**Examples**:
- `BigQuery:bigquery_schema`
- `Notion:query_database`

## Changed Patterns (2025 → 2026)

| Pattern | 2025 | 2026 | Migration |
|---------|------|------|-----------|
| Hooks | Conceptual | Production-ready (Q1 2026) | Configure hooks in CI pipeline |
| Headless mode | Basic | Multiple output formats (JSON, streaming) | Use `--output-format json` for automation |
| GitLab CI | Manual | Official integration docs | Configure hooks in .gitlab-ci.yml |
| MCP integration | N/A | `claude mcp add` command | Use qualified names (Server:tool) |

## Anti-Patterns

| Anti-Pattern | Problem | Correct |
|--------------|---------|---------|
| Manual quality gates | Inconsistent enforcement | Use hooks for automatic execution |
| `--dangerously-skip-permissions` in production | Security risk | Use sandbox mode or containerized environment |
| Unqualified MCP tool names | "tool not found" errors | Use `ServerName:tool_name` format |
| Skipping PR status checks | Broken code merged | Require all checks to pass before merge |
| No rollback plan | Deployment failures unrecoverable | Always have automated rollback |

## Examples

### Example 1: GitHub Actions Quality Gate with Hooks

**Workflow** (`.github/workflows/quality-gates.yml`):
```yaml
name: Quality Gates
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  gates:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup
        uses: actions/setup-node@v4
        with:
          node-version: '20'

      - name: Install
        run: npm ci

      - name: Run Claude hooks
        run: |
          # Pre-commit hook
          node .claude/hooks/pre-commit.js

      - name: Quality gates
        run: |
          npm run lint
          npm test
          npm run test:e2e -- --grep @p0

      - name: Post results
        if: always()
        uses: actions/github-script@v7
        with:
          script: |
            const status = context.payload.workflow_run.conclusion;
            const message = status === 'success'
              ? '✅ All quality gates passed'
              : '❌ Quality gates failed';
            github.rest.issues.createComment({
              issue_number: context.issue.number,
              owner: context.repo.owner,
              repo: context.repo.repo,
              body: message
            });
```

### Example 2: Headless CI Script

**Script** (`scripts/ci-review.sh`):
```bash
#!/bin/bash
set -e

# Get diff
git diff origin/main...HEAD > diff.txt

# Review with Claude (headless mode)
claude -p "Review this diff for security issues and code quality. Output JSON with findings." \
  --output-format json \
  < diff.txt \
  > review.json

# Parse results
if jq -e '.findings | length > 0' review.json; then
  echo "Review found issues:"
  jq '.findings' review.json
  exit 1
else
  echo "Review passed"
  exit 0
fi
```

**Usage in CI**:
```yaml
- name: Claude review
  run: bash scripts/ci-review.sh
```

### Example 3: GitLab CI with MCP

**GitLab CI** (`.gitlab-ci.yml`):
```yaml
stages:
  - quality
  - deploy

quality-gates:
  stage: quality
  script:
    - npm ci

    - npm test

    - |
      claude -p "Post test results to Notion board" \
        --output-format json \
        < test-results.json

    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
```

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Hooks not executing in CI | Check hook file is executable (`chmod +x`) |
| Headless mode timeout | Use streaming output (`--output-format stream-json`) |
| MCP tool not found | Use fully qualified name (`ServerName:tool_name`) |
| Autonomous mode security concerns | Only use in isolated container, prefer sandbox mode |
| GitLab CI hooks failing | Check hooks configured in `.gitlab-ci.yml` stages |
