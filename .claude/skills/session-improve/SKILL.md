# Session Improve Skill

Unified skill for the session review cycle: analyze session logs, identify failure patterns, and apply ecosystem improvements.

## Subcommand Dispatch

Parse the first argument to determine which subcommand to run:

| Subcommand | Description | Previous Skill |
|------------|-------------|----------------|
| `review` | Analyze Claude Code session logs for patterns, problems, and improvements | `session-review` |
| `analyze` | Analyze failure patterns across features and suggest CLAUDE.md improvements | `failure-analyze` |
| `apply` | Review findings and apply approved improvements to CLAUDE.md, skills, agents | `ecosystem-improve` |
| _(no args)_ | Display usage help showing available subcommands | - |

### Usage Help (no args)

When invoked without arguments, display:

```markdown
## session-improve - Session Review Cycle

Available subcommands:

| Subcommand | Usage | Description |
|------------|-------|-------------|
| `review` | `session-improve review [--since DATE] [--cycle] [--all] [--session ID]` | Analyze session logs |

| `apply` | `session-improve apply [--auto-p1] [--dry-run] [--claude-only]` | Apply improvements |

Typical cycle: review -> analyze -> apply
```

## Subcommand: review

Analyze Claude Code session logs from `~/.claude/` to identify recurring problems, workflow friction, and improvement opportunities. Uses subagents for parallel analysis of session transcripts.

### Overview

This subcommand reads local Claude Code session data to find:
- Recurring user complaints or frustrations
- Common errors and their root causes
- Workflow bottlenecks
- Patterns that should be documented in CLAUDE.md
- Skill/agent gaps

### Parameters

| Parameter | Required | Default | Description |
|-----------|----------|---------|-------------|
| `--since [date]` | No | Last 7 days | Analyze sessions since date (YYYY-MM-DD) |
| `--cycle` | No | Disabled | Use last review date from context.md |
| `--all` | No | Disabled | Analyze all sessions (caution: large data) |
| `--session [id]` | No | - | Analyze specific session only |

### Data Sources

| Source | Path | Purpose |
|--------|------|---------|
| Sessions Index | `~/.claude/projects/[project]/sessions-index.json` | Session metadata |
| Session Transcripts | `~/.claude/projects/[project]/*.jsonl` | Full conversations |
| Prompt History | `~/.claude/history.jsonl` | All prompts across sessions |
| Subagent Metrics | `~/.claude/subagent-metrics.log` | Subagent performance |
| Session Metrics | `~/.claude/session-metrics.log` | Stop reasons, durations |

### Execution Flow

1. **Determine Time Boundary** from `--since`, context.md last review date, or default 7 days
2. **Load Session Index** and filter by time
3. **Categorize Prompts** from history.jsonl (questions, commands, corrections, frustrations)
4. **Spawn Analysis Subagents** for sessions with >20 messages
5. **Aggregate Findings** into unified report (errors, frustrations, workflow issues)
6. **Generate Recommendations** prioritized by frequency and impact (P1/P2/P3)
7. **Update Review Tracking** in context.md

### Output Format

```markdown

**Generated**: [TIMESTAMP]
**Project**: [PROJECT_PATH]
**Time Range**: [SINCE] to [NOW]

| Session ID | Started | Duration | Stop Reason | Tools Used | Issues Found |
|------------|---------|----------|-------------|-----------|--------------|
| [session-id-1] | [ts] | [Xm] | [reason] | [N tools] | [count] |
| ... | | | | | |

## Executive Summary
- **Total Issues Found**: [X]
- **Critical (P1)**: [Y]
- **High (P2)**: [Z]

## Top 5 Findings

...

## Detailed Analysis

### Recurring User Frustrations
- [Quote or pattern from session transcripts]
- [Frequency: N sessions]
```

> **Format-contract note**: the `<!-- Generated by /session-improve review on [TIMESTAMP] -->` marker is the canonical signal for downstream tools (`apply-learnings`, `context-sync`, `skill-audit`) to programmatically locate exported review sections. ## Subcommand: analyze

Analyze failure patterns from context.md files across features, identify high-impact issues, and suggest improvements to CLAUDE.md, skills, and workflows.

### Parameters

| Parameter | Required | Default | Description |
|-----------|----------|---------|-------------|
| `--feature [name]` | No | All features | Analyze single feature |
| `--export` | No | Disabled | Generate CLAUDE.md additions only |
| `--metrics` | No | Disabled | Show metrics dashboard only |

### Execution Flow

1. **Gather Failure Data** from all `specs/*/context.md` files
2. **Aggregate Patterns** into master table with priority (P1-P4)
3. **Compare Against CLAUDE.md** for gap analysis (documented, effective, missing)
4. **Generate Improvement Proposals** for undocumented patterns with count >= 3
5. **Skill Improvement Suggestions** if patterns indicate skill gaps
6. **Priority Dashboard** sorted by impact
7. **Increment Tracking** in each feature's context.md
8. **Export Lessons Learned** as CLAUDE.md additions, prefixed with the marker
   `<!-- Generated by /session-improve analyze on [DATE] -->` so downstream tools can
   locate exported sections. **Back-compat**: ALSO emit the legacy
   `<!-- Generated by /failure-analyze on [DATE] -->` marker for one release cycle.

**Priority Calculation**:
- P1 (Critical): Count >= 5 OR Category in (API, DOCKER, DB)
- P2 (High): Count >= 3
- P3 (Medium): Count >= 2
- P4 (Low): Count = 1

### Auto-invocation (subcommand-level override)

The skill's `disable-model-invocation: true` (frontmatter) prevents model auto-invocation by default. The `analyze` subcommand specifically supports auto-invocation when failure patterns reach P1 thresholds (matching the legacy `failure-analyze` skill's `disable-model-invocation: false` behavior). If the parent skill setting blocks auto-invocation in the model's discovery, the runtime can opt into auto-`analyze` via the `session-end.js` hook's reminder mechanism — which already triggers `/session-improve apply --auto-p1` on threshold breach. For pure auto-analyze (no apply), invoke explicitly: `/session-improve analyze`.

> **TODO**: revisit when Claude Code supports subcommand-level `disable-model-invocation` overrides. At that point the `analyze` subcommand should be configured `disable-model-invocation: false` to restore the legacy `failure-analyze` auto-invocation behavior natively, removing the dependency on the `session-end.js` reminder workaround.

## Subcommand: apply

Review findings from `session-improve review` and `session-improve analyze`, generate improvement proposals, then apply user-approved changes.

### Parameters

| Parameter | Required | Default | Description |
|-----------|----------|---------|-------------|
| `--auto-p1` | No | Disabled | Auto-apply P1, ask for others |
| `--dry-run` | No | Disabled | Preview only |
| `--claude-only` | No | Disabled | Only update CLAUDE.md |

### Workflow

1. **Gather Sources** - Read context.md, CLAUDE.md, skills/, agents/
2. **Generate Proposals** - Create specific proposals for each finding
3. **Present for Review** - User approves/rejects each proposal
4. **Apply Approved** - Edit files with approved changes
5. **Validate** - Verify files are valid, run lint checks
6. **Cleanup context.md** - Remove exported lessons, reset patterns
7. **Commit** - Stage changes, create conventional commit using the template:

   ```
   chore(ecosystem): apply session improvements

   - <count> CLAUDE.md additions
   - <count> skill updates
   - <count> agent updates

   Source: /session-improve apply on <date>
   ```

   (Legacy callers may prefer `chore(ecosystem): apply session review improvements`. Either is accepted by the kit; the format above is canonical going forward.)
8. **Report** - Summary of applied changes

### Safety

1. **Backup**: Creates `.backup` files before editing
2. **Validation**: Checks syntax after changes
3. **User control**: All changes require approval by default

## Best Practices

This skill inherits the kit-wide best practices from `.claude/rules/skill-standards.md` § Dimension 2:

- **FETCH BEFORE CITE** — read source files before claiming behavior; never reference a function or contract without opening it (per `rules/verification-protocol.md`)
- **Anti-hallucination** — when a category produces no findings, state that explicitly. Never pad to fill the category
- **Output Contract** — every emitted finding/artifact carries: severity tag (`BLOCKING` / `MUST-FIX` / `SHOULD-FIX` / `CONSIDER` / `PRAISE`) + file:line + evidence (≤6 lines) + cited rule + suggested fix
- **Confidence floor** — emit at confidence ≥ severity-floor (BLOCKING ≥80, MUST-FIX ≥70, SHOULD-FIX ≥60, CONSIDER ≥50, PRAISE ≥70)
- **Existing-thread dedup** — when consuming prior threads/comments, suppress findings within ±5 lines of resolved threads
- **WorkIQ context** — auto-trigger when artifact references a work item / feature area / known author; graceful-degrade when MCP is unavailable
- **Auto-fan-out** — when ≥3 confirm-asks accumulate at confidence 40-69, READ the referenced files in full and re-evaluate
