## Implementation summary

`packages/engine-core/src/index.ts` — minimal lifecycle loop:

1. Validate `maxCycles` (positive integer).
2. Push `'open'` then `'active'` to lifecycle.
3. Compute `cyclesToRun = min(maxCycles, MAX_CYCLES_HARD_CAP=50)` and `willHitCap = maxCycles >= 50`.
4. Loop `cyclesToRun` times: append `{cycle, hash: sha256(prior|cycle|state), state: 'active'}` audit entry.
5. Push `'closing'` then `'closed'` to lifecycle (always — F-014 retro-signal seam).
6. Return with `terminatedBy: willHitCap ? 'cycle_cap' : 'completion'`.

Type surface includes `'exception'` variant for `terminatedBy` so scenario 3's union check passes; F-021 will wire the actual exception-injection seam without breaking this contract.

## Toolchain hops

Three small fixes landed alongside F-001's impl:

1. **`pnpm-workspace.yaml`** — pnpm v10+ ignores `workspaces` in package.json, emits a warning, and fails to symlink workspace packages. Adding the YAML file is the documented fix.
2. **`@mad-council-claw/engine-core: workspace:*` devDep on root** — without this, the workspace package isn't symlinked into root `node_modules/@mad-council-claw/`, so `import { bootstrap } from '@mad-council-claw/engine-core'` in the test fails with "Failed to load url".
3. **`test:unit` script** — changed `vitest run --project unit` → `vitest run tests/unit`. Vitest 2.1.9's `--project <name>` filter wasn't matching despite the `vitest.config.ts` defining `name: 'unit'`. Path-glob filter is version-tolerant and gives the same effect.

All three follow `minimum-change.md` — the smallest fix that unblocks the test, no broader toolchain refactor.
