## Multi-instance pickup protocol

> Per the user's directive: "as new questions come up new copilot/clauce code instances/sessions/subagents."

Any fresh Claude Code session, Copilot CLI invocation, Anthropic SDK session, or other agent can pick up loop work by following this protocol:

1. **Read** `docs/11-loop-state/current-wave.md` — tells you what wave is running and where the pickup points are.
2. **Read** `docs/01-requirements/session-requests.md` + `goals.md` — the foundational context.
3. **Read** `docs/10-backlog/README.md` — pick an item from `research-gaps.md`, `implementation-todo.md`, or `design-decisions-pending.md`.
4. **Claim** the item by appending a row to `docs/11-loop-state/current-wave.md` with: instance type (claude-code-N / copilot-cli / subagent-X), claimed item ID, ETA.
5. **Execute** per the rules in `docs/12-resource-roster/<your-instance-type>.md`.
6. **Output** to `docs/06-agent-team-outputs/wave-NNN/lane-<your-handle>-<topic>.md`.
7. **Commit + PR** per micro-session discipline (one feature/topic per PR).
8. **Mark** the claimed backlog item resolved (or partial; back to backlog with progress note).

This keeps multi-instance work coordinated without central locking — file-based claims are atomic per `concurrency-safety.md` write-temp-rename pattern.

RELATED: <links to related backlog items, decisions, prior commits>

## Backlog management (what gets added to / removed from the loop)

> Per the user's directive: "as new items get added to the loop. we should keep medium and high confidence items."

### Intake protocol

New items enter the backlog via:
- User asks a question or surfaces a requirement (mid-loop or at periodic interview gates) → append to `docs/10-backlog/open-questions.md`
- A wave finds a research gap → append to `docs/10-backlog/research-gaps.md`
- A wave proposes a design decision → append to `docs/10-backlog/design-decisions-pending.md`
- A feature is identified but not yet implemented → append to `docs/10-backlog/implementation-todo.md`
- A rule recurs as a correction ≥3 times → append to `docs/10-backlog/feature-promotions.md` per `rules-without-hooks-audit.md` discipline
- A tool / surface is flagged ACTIVE→OBS or OBS→RETIRED → append to `docs/10-backlog/retire-candidates.md`

### Confidence labeling

Every backlog entry tags confidence:
- **HIGH (≥80%)**: enough evidence to act; auto-pickup eligible by next available instance
- **MEDIUM (50-79%)**: enough evidence to track; requires more research or user input before action; KEPT in backlog
- **LOW (<50%)**: insufficient evidence; either dropped (with rationale) OR moved to `research-gaps.md` for evidence-gathering wave

### Aging + escalation

- Items aged >30 days without action → flag in `docs/10-backlog/README.md` for periodic interview gate (L3)
- Items in MEDIUM confidence for >5 waves without promotion to HIGH → research-wave priority

### Removal

- HIGH item executed → moved to `docs/07-roadmap/decision-log.md` with date + outcome
- LOW item dropped → moved to `docs/10-backlog/dropped-with-rationale.md` (audit trail)
- Per `no-silent-deferrals.md`: removals require explicit user acknowledgement at periodic interview gate (L3)
